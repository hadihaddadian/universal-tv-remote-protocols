# Universal TV Remote V63

Universal TV Remote is an Android application for controlling compatible TVs over IR and local-network protocols.

## Current release
- `versionCode = 62`
- `versionName = 62`
- Android Gradle Plugin 8.7.3
- Kotlin 2.0.21
- Java 17
- compileSdk / targetSdk 35
- minSdk 26

## Architecture
The runtime has one canonical path:

`DiscoveryCoordinator → ProtocolManager → ProtocolBindingRegistry → compiled transport → command dispatcher`

Remote protocol packages are declarative data only. They are accepted only after size, schema, compatibility, SHA-256 and signature validation; executable code is never downloaded as a protocol update.

## Implemented
- SSDP + Android TV Remote v2 NSD discovery through one coordinator
- Android TV Remote v2 pairing/control with the established v2 Protobuf wire schema, protocol-version-2 pairing flow, and per-device server-certificate pinning
- Samsung WebSocket, LG webOS SSAP, Sony BRAVIA IRCC, Philips JointSpace, Roku ECP, and a built-in IR transport with an explicit default NEC profile (not a universal IR-code database)
- Encrypted credential storage backed by Android Keystore
- Canonical capability model and runtime capability projection
- Bounded reconnect/re-discovery after connection failure
- Transport health checks where the protocol adapter can provide one; otherwise `UNKNOWN`
- Atomic protocol installation and corruption quarantine
- Protocol distribution service foundation with signed declarative packages
- Single GitHub Actions verification/build workflow

## Explicit limitations
- LG pointer-input navigation (Up/Down/Left/Right/Home/Back) is implemented as a capability-gated gesture fallback; true vendor pointer semantics remain model/protocol dependent. Android TV voice is now wired through runtime microphone permission and the Remote v2 voice transport. Android TV text input, App Link launching, persisted app favorites, device favorites, macros, numeric keypad, playback controls and safe diagnostics are executable in V63.
- Hardware validation on physical TV models is not claimed by source inspection alone. Network protocols are implemented from documented/reverse-engineered protocol schemas, but model/firmware differences still require hardware certification.
- The repository intentionally does not contain a fabricated `gradle-wrapper.jar`. CI provisions Gradle 8.11.1 explicitly until a genuine wrapper is generated by a real Gradle distribution.

## Protocol distribution configuration
Remote protocol updates are disabled by default. A production build must explicitly provide both `protocolRepositoryUrl` and its matching `protocolRepositoryPublicKey`. The trust anchor has no development-key fallback; an incomplete remote configuration fails closed.
